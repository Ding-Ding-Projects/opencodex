title: Быстрый старт
description: Запустите opencodex с существующим входом ChatGPT/Codex; для локальной работы API-ключ провайдера не нужен.
---

Свежая локальная конфигурация использует встроенный провайдер `openai`, который пересылает ваш
существующий вход ChatGPT/Codex. Перед первым запуском **не нужно** получать API-ключ провайдера
или выполнять `ocx init`.

## 1. Запустите прокси

```bash
ocx start            # порт по умолчанию 10100
ocx start --port 8080
```

Оставьте этот терминал открытым. При запуске opencodex:

- загружает не требующий ключа ChatGPT-forward провайдер, если конфигурации ещё нет;
- записывает PID в `~/.opencodex/ocx.pid` и не допускает повторный запуск;
- синхронизирует доступные модели с каталогом моделей Codex;
- обратимо добавляет локальный прокси в конфигурацию Codex;
- слушает `http://localhost:<port>/v1`.

Если порт занят, opencodex записывает свободный порт в `runtime-port.json` и обновляет Codex.
Проверить состояние или открыть панель управления можно из другого терминала:

```bash
ocx status
ocx gui
```

## 2. Используйте вход ChatGPT/Codex

Если Codex уже вошёл в ChatGPT, больше ничего настраивать не нужно. В противном случае один раз
выполните обычный вход Codex:

```bash
codex login
```

Затем запустите Codex, уже подключённый к работающему прокси:

```bash
ocx codex
```

Нативные id моделей без пространства имён, например `gpt-5.6-sol`, используют встроенный маршрут
ChatGPT-forward. Запись в каталоге сама по себе не выдаёт доступ: аккаунт должен иметь право на модель.

## Какие учётные данные запрашиваются?

| Учётные данные | Когда нужны | Что это |
| --- | --- | --- |
| **Вход ChatGPT/Codex** | Локальный маршрут `openai` по умолчанию | Сессия аккаунта, созданная `codex login` или приложением Codex. Это не API-ключ. |
| **Учётные данные вышестоящего провайдера** | Только после явного добавления другого провайдера | API-ключ или OAuth/вход в аккаунт этого провайдера. Локальным провайдерам обычно не нужно ни то, ни другое. |
| **Ключ доступа OpenCodex** | Клиенты data plane, подключённые к не-loopback/LAN-привязке | Создаётся `ocx host enable --new-key --yes` и защищает `/v1/*`. Это не платёжный ключ провайдера; на `localhost` он не нужен. |

Сообщение **`opencodex API key required`** означает, что клиент подключился к не-loopback слушателю
без ключа доступа OpenCodex. Используйте `localhost` или настройте сгенерированный ключ в клиенте.
Покупка или вставка API-ключа провайдера это сообщение не исправит.

## 3. Добавьте другого провайдера (необязательно)

Проще всего открыть `ocx gui` и выбрать **Add provider**: вход в аккаунт, API-ключ, локальный сервер
или собственную конечную точку. Для изменения свежей конфигурации из терминала используйте:

```bash
ocx init
```

В приглашении **Select default provider** клавиша <kbd>Enter</kbd> выбирает провайдера **1** —
**OpenAI — ChatGPT login (no key)**. Мастер запрашивает только то, что нужно выбранному маршруту:

1. **ChatGPT forward** — API-ключ не нужен; используется вход Codex.
2. **Вход в аккаунт (OAuth)** — сохраните провайдера, затем выполните показанную команду
   `ocx login <provider>`.
3. **Провайдер с API-ключом** — укажите ключ этого вышестоящего провайдера или ссылку на переменную
   окружения, например `${ANTHROPIC_API_KEY}`.
4. **Локальный провайдер** — обычно оставьте ключ пустым.
5. **Прокси и интеграция Codex** — выберите порт, внедрение и необязательный shim автозапуска.

Результат сохраняется в `$OPENCODEX_HOME/config.json` (по умолчанию `~/.opencodex/config.json`).

:::note[Записи каталога GPT-5.6]
Стабильная версия v2.7.1 добавляет GPT-5.6 Sol/Terra/Luna для ChatGPT passthrough, OpenAI по
API-ключу, OpenRouter и экспериментального Cursor. Они работают только при наличии доступа у
соответствующего вышестоящего аккаунта.
:::

Для конкретной маршрутизируемой модели используйте форму `provider/model` из селектора Codex:

```bash
codex -m "anthropic/claude-opus-5" "Explain this stack trace"
codex -m "ollama-cloud/glm-5.2"      "Write a SQL migration"
```

## Выбор моделей подагентов (необязательно)

В свежей конфигурации доступны `gpt-5.5`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` и
`gpt-5.4-mini`. В `ocx gui` можно заменить или переупорядочить до пяти нативных или
маршрутизируемых моделей.

## Вход в аккаунт необязательного провайдера

Некоторые провайдеры поддерживают OAuth-вход:

```bash
ocx login xai          # или: anthropic, kimi, kiro, google-antigravity, cursor
ocx logout xai
```

Маршруту OpenAI по умолчанию **не нужен ключ провайдера**: он пересылает существующие учётные данные
`codex login`. Подробнее: [Провайдеры](/ru/guides/providers/).

## Остановка и восстановление

```bash
ocx stop          # остановить прокси и восстановить нативный Codex
ocx restore       # восстановить нативный Codex без остановки (псевдоним: ocx eject)
ocx restore back  # снова направить Codex через работающий прокси
```
